# NYC Payroll Data Engineering (Azure)

## Project overview
Azure data platform that loads NYC payroll CSV files from ADLS Gen2 into Azure SQL Database with Azure Data Factory (Mapping Data Flows), builds a payroll summary by fiscal year and agency, and exposes it for public analysis through a Synapse serverless SQL external table.

## Business objectives
1. Analyze how NYC financial resources are allocated.
2. Analyze how much of the City budget goes to overtime.
3. Make salary, overtime and total payroll data available for public analysis.
4. Provide dynamic, automatable, monitorable and testable pipelines.

## Architecture
See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Source: ADLS Gen2 -> ADF data flows -> Azure SQL `db_nycpayroll` -> `DF_PAYROLL_SUMMARY` -> Azure SQL summary table + ADLS `dirstaging` -> Synapse serverless external table (`udacity` database).

## Required Azure resources
Storage account (ADLS Gen2, hierarchical namespace ON), Azure SQL Database `db_nycpayroll`, Azure Data Factory (Git-connected to this repository), Synapse workspace (serverless SQL only), GitHub repository.

## Data flows
- `DF_LOAD_EMP_MASTER`, `DF_LOAD_AGENCY_MASTER`, `DF_LOAD_TITLE_MASTER`: ADLS CSV -> SQL, sink with **truncate** (rerunnable, no duplicates on rerun).
- `DF_LOAD_PAYROLL_2020`, `DF_LOAD_PAYROLL_2021`: source columns read as strings, then explicit conversion (`toInteger`, `toDouble`, `toDate(..., 'M/d/yyyy')`), sink with **truncate**. Schema drift disabled; all 19 columns mapped explicitly.
- `DF_PAYROLL_SUMMARY`: Source 2020 -> Select -> Source 2021 -> Select (`AgencyCode` mapped to `AgencyID`) -> Union (by name) -> Filter `toInteger(FiscalYear) >= $dataflow_param_fiscalyear` -> Derived `TotalPaid = coalesce(RegularGrossPaid,0.0)+coalesce(TotalOTPaid,0.0)+coalesce(TotalOtherPay,0.0)` -> Aggregate by `FiscalYear, AgencyName` (`sum(TotalPaid)`) -> sink SQL `dbo.NYC_Payroll_Summary` (truncate) and sink ADLS `dirstaging` (clear folder, single file, no header).

## Pipeline dependency sequence
```
Stage 1 (parallel): Load Agency Master | Load Employee Master | Load Title Master
   -- all Succeeded -->
Stage 2 (parallel): Load Payroll 2020 | Load Payroll 2021
   -- both Succeeded -->
Stage 3: Build Payroll Summary (DF_PAYROLL_SUMMARY)
```

## Schemas
Defined in [sql/01_create_azure_sql_tables.sql](sql/01_create_azure_sql_tables.sql). The 2020 table uses `AgencyID`; the 2021 table uses `AgencyCode`. Summary: `FiscalYear int, AgencyName varchar(50), TotalPaid float`.

## Parameterization
- Global parameter `global_param_fiscalyear` (int, default 2020; use 2020 or 2021).
- Pipeline passes `@pipeline().globalParameters.global_param_fiscalyear` to `DF_PAYROLL_SUMMARY.dataflow_param_fiscalyear` (integer).

## Known issues
- The ADF JSON here was authored offline and has **not been opened in ADF Studio or deployed**. Open each data flow in ADF Studio, check there are no validation errors, then Save/Publish.
- Linked service credentials are placeholders and must be set in ADF Studio (or Key Vault).
- Azure SQL linked service may need Version = Legacy (see [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)).
- Source files contain 1 row with FiscalYear 1998 (2020 file) and 1 row with 1999 (2021 file).
- Troubleshooting: [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

## Security considerations
No keys, passwords, SAS tokens, connection strings with secrets, or subscription/tenant IDs are committed. Placeholders: `<STORAGE_ACCOUNT_NAME>`, `<SQL_ADMIN_LOGIN>`, `<FILE_SYSTEM_NAME>`. Synapse reads ADLS via Entra user pass-through. Confirm the CSV data is public NYC Open Data before publishing. Crop subscription IDs out of screenshots.
